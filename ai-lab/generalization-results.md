## Detailed Analysis

### Experiment 1: Train/Test Split — GENERALIZES

```
Train: 124,552 chars (80%)
Test:  31,138 chars (20%) — NEVER SEEN

Train accuracy (online):       58.37%
Test accuracy (online):        57.03%   <-- gap only 1.34%
Strict test (NO learning):     49.47%   <-- knows half without seeing test data
```

**Verdict**: Architecture G genuinely generalizes. The 1.34% train-test gap is remarkably small. Even in strict mode (no learning during test), it predicts half the characters correctly. This is NOT pure memorization — it has learned statistical patterns of French that apply to unseen text.

The 99.95% from evolve.py was on repeated text (pre-trained then re-tested on same data). The REAL accuracy on unseen text is ~57% online, ~49% strict. Still impressive for character prediction.

### Experiment 2: Cross-Domain Transfer

```
French -> NB-1 compressed text:  +10.89% boost from pre-training
French -> Python source code:    -2.03% (slight hurt)
```

French pre-training helps with NB-1 because NB-1 is still French-derived compressed text. It hurts slightly on Python because French letter patterns interfere with code patterns (e.g., predicting "u" after "q" when the code has "query").

### Experiment 3: Online Learning Curve

```
After 100 chars:  11% accuracy (guessing)
After 400 chars:  26% (learning basic patterns)
After 800 chars:  39% (rolling window)
After 2000 chars: 48% (rolling window)
```

It reaches useful accuracy within ~400 characters — about 2 paragraphs. The learning never stops; it keeps improving as more text is seen.

### Experiment 4: Architecture G vs Baselines

```
Most common char (space):  13.92%

Markov order-3:            45.47%
Architecture G (depth=16): 57.03%
```

Architecture G is 1.3x better than a Markov-3. The weighted voting across all depths is the key differentiator — it's not just a deeper Markov chain, it's an ensemble of 16 Markov chains voting together.

### Experiment 5: What It Learned

It genuinely learned French:
- After "q", predict "u" (99% confidence) — French orthography
- After ". ", predict uppercase (95.8%) — capitalization rules
- After "c'es", predict "t" (100%) — "c'est" is the most common French contraction
- After "tion", predict " " (51%) — word endings
- After "que ", predict "j" (23%) — "que je" is a common French bigram

### Experiment 6: Hybrid with LLM — Surprising Result

The LLM (Llama-3.1-8B via SambaNova) scored only 10% on the characters where Architecture G was uncertain. Single character prediction without full context is hard even for LLMs. Architecture G already handles 76% of predictions with high confidence (70% accuracy on those). The hybrid approach doesn't help — G's uncertainty cases are genuinely hard.

### Experiment 7: Scale — Saturates Gracefully

```
152 KB data:  109.3 MB memory, 9,375 chars/sec
1.5 MB data:  109.3 MB memory, 11,523 chars/sec (FASTER)
```

Memory stays constant because the dictionary of character patterns saturates. After ~150K chars of French, most character n-grams have been seen. More data doesn't grow the dictionary, it just strengthens existing patterns. Speed actually increases because cache locality improves.

## The Verdict

**Architecture G is more than a lookup table, but less than an AI.**

It is a multi-scale statistical model that genuinely learns and generalizes patterns in language. The 1.34% train-test gap proves it's not just memorizing. The 49.47% strict accuracy proves it has internalized French structure.

But it's fundamentally a character-level Markov ensemble. It cannot:
- Understand meaning
- Generate coherent text
- Reason about concepts
- Transfer across unrelated domains

What it CAN do:
- Predict the next character with ~57% accuracy on unseen French text
- Learn a new text's patterns within 400 characters
- Scale to megabytes of data without memory explosion
- Run at 10K+ characters per second

**It's the best possible version of "just counting patterns." And that's honestly interesting.**
